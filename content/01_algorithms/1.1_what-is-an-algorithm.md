# 1.1 What Is an Algorithm?

## Learning Goals

After reading this section, you should be able to:

1. **Explain** what an algorithm is in your own words.
2. **Identify** the five properties every algorithm should have.
3. **Trace** a simple algorithm step by step with pen and paper.
4. **Distinguish** between an algorithm and a program.
5. **Write** an everyday task as an algorithm with a clear input and output.

## Key Terms

| Term | Meaning |
|---|---|
| **Algorithm** | A finite, step-by-step set of clear instructions that solves a problem or completes a task. |
| **Input** | The information you give to an algorithm before it starts. |
| **Output** | The result the algorithm gives back when it is done. |
| **Step** | One single instruction in an algorithm, such as "add 1 to x". |
| **Finiteness** | The algorithm must stop after a limited number of steps. It cannot run forever. |
| **Definiteness** | Every step must be clear and have only one meaning, so there is no guessing. |
| **Pseudocode** | A way of writing an algorithm that looks like code but is not tied to any real programming language. |
| **Program** | An algorithm written in a real programming language, such as Python, so a computer can run it. |

## Definition

An **algorithm** is a finite, well-defined sequence of steps for solving a problem or completing a task. It takes some **input**, processes it through clear instructions, and produces an **output** (Cormen et al., 2022). An algorithm describes *what to do and in what order*, in enough detail that a person or a machine can follow it without having to guess.

Algorithms are not limited to computers. A cooking recipe, the steps for long division, and directions to a friend's house all work in a similar way. Computer science, however, requires algorithms to be completely precise, because a computer follows exactly the instructions it is given.

## A Brief History

The word *algorithm* comes from the name of **Muhammad ibn Musa al-Khwarizmi** (c. 780–850), a Persian mathematician who worked at the House of Wisdom in Baghdad. His book on calculating with Hindu-Arabic numerals was translated into Latin as *Algoritmi de numero Indorum*. Over time, "Algoritmi" became the word for a step-by-step method of calculation.

The idea is much older than the word. **Euclid's algorithm** for finding the greatest common divisor of two numbers appears in Euclid's *Elements* (c. 300 BCE) and is still used today. In the 20th century, mathematicians such as Alan Turing and Alonzo Church gave the idea a formal definition, which became one of the foundations of modern computer science.

## Key Properties

Every algorithm should have five properties:

| Property | Meaning |
|---|---|
| **Finiteness** | It must stop after a finite number of steps. |
| **Definiteness** | Each step is precise and unambiguous. |
| **Input** | It takes zero or more inputs. |
| **Output** | It produces at least one output that is related to the input. |
| **Effectiveness** | Each step is simple enough to be carried out exactly, in a finite amount of time. |

A procedure that runs forever, or that contains a vague step such as "pick a good number", is not an algorithm in this strict sense.

## How Algorithms Are Represented

The same algorithm can be written in plain language, in pseudocode, as a flowchart (a diagram of boxes connected by arrows), or as real code in a programming language. Plain language is easy to read, while code can actually be run by a computer. More in section 1.2.

## Example 1: Finding the Largest Number in a List

**Natural language:**

1. Set `max` to the first number in the list.
2. For each remaining number, if it is greater than `max`, set `max` to that number.
3. When every number has been checked, return `max`.

**Pseudocode:**

```
FIND-MAX(A)
    max ← A[1]
    for i ← 2 to length(A)
        if A[i] > max
            max ← A[i]
    return max
```

**Python:**

```python
def find_max(numbers):
    largest = numbers[0]
    for n in numbers[1:]:
        if n > largest:
            largest = n
    return largest
```

This example has all five properties. It stops once the list ends, every step is clear, it takes a list as input, it returns the largest value as output, and each comparison is a simple operation.

## Example 2: Euclid's Algorithm (Greatest Common Divisor)

The greatest common divisor (GCD) of two numbers is the biggest number that divides both of them with no remainder. In the pseudocode below, `a mod b` means "the remainder when a is divided by b".

```
GCD(a, b)
    while b ≠ 0
        r ← a mod b
        a ← b
        b ← r
    return a
```

**Trace for GCD(48, 18):**

| a | b | a mod b |
|---|---|---|
| 48 | 18 | 12 |
| 18 | 12 | 6 |
| 12 | 6 | 0 |
| 6 | 0 | (loop stops) |

Result: **6**. Each step makes `b` smaller, so the loop is guaranteed to stop. This is the finiteness property in action.

## Algorithm vs. Program

The two terms are related but not identical:

- An **algorithm** is the abstract *idea* or method for solving a problem, independent of any language or machine.
- A **program** is a concrete *implementation* of one or more algorithms in a specific programming language.

The same algorithm (for example, binary search) can be implemented as many different programs in Python, Java, or C++.

## Measuring Efficiency

Different algorithms can solve the same problem, but some are much faster or use less memory than others. Computer scientists compare them by how the amount of work grows as the input gets bigger, and they often write this using **Big-O notation**, a short way to describe that growth (Cormen et al., 2022). For example, finding an item in a sorted list of one million items can take up to one million checks if you look one by one, but only about 20 checks with binary search, which looks at the middle and throws away half the list each time. More in section 1.3.

## Common Types of Algorithms

Algorithms are often grouped by the kind of problem they solve or the strategy they use. For example, **searching** algorithms find an item in a collection, and **sorting** algorithms put items in order. More in sections 1.3 and 1.4.

## Algorithms in Everyday Life

Algorithms run behind many everyday technologies:

- **Navigation apps** use shortest-path algorithms to find routes.
- **Search engines** use ranking algorithms to order results.
- **Recommendation systems** suggest videos, music, or products based on past behavior.
- **Encryption algorithms** protect online banking and messaging.
- **Compression algorithms** make images, audio, and video files smaller.

## Conclusion

An algorithm is a precise, finite set of steps that turns input into output. Good algorithms are correct, unambiguous, and efficient. Because the same problem can often be solved in many ways, understanding how to design and analyze algorithms is one of the most important skills in computer science.

## Activity

Try these with pen and paper before you look at the answers.

1. **Trace FIND-MAX** on the list `4, 9, 2, 7`. Write down the value of `max` after each step.
2. Is the instruction **"pick a good number and add it"** an algorithm? If not, which property does it break?
3. Write the steps for **making a cup of tea** as an algorithm. State the input and the output clearly.

## Answers

### 1. Trace of FIND-MAX on 4, 9, 2, 7

| Step | Number checked | Is it bigger than `max`? | `max` after this step |
|---|---|---|---|
| Start | 4 (first number) | (no check, just set it) | 4 |
| 1 | 9 | Yes, 9 > 4 | 9 |
| 2 | 2 | No, 2 < 9 | 9 |
| 3 | 7 | No, 7 < 9 | 9 |

**Output: 9.** The algorithm checked every number once and then stopped, so it is finite. Each step only needs one simple comparison.

### 2. "Pick a good number and add it"

**No, it is not an algorithm.** It mainly breaks **definiteness**. The word "good" has no exact meaning, so two people could pick two different numbers. The instruction also does not say *what* to add the number to, so the **input** and **output** are unclear too. A fixed version could be: "Take the number x. Add 5 to it. Give back the result."

### 3. Making a cup of tea

**Input:** a cup, a tea bag, water, and a kettle.
**Output:** one cup of hot tea.

1. Fill the kettle with water.
2. Switch on the kettle and wait until the water boils.
3. Put the tea bag in the cup.
4. Pour the hot water into the cup until it is almost full.
5. Wait 3 minutes.
6. Take the tea bag out of the cup.
7. Give the cup of tea to the person.

**Why this is an algorithm:** it has a clear input and output, it stops after 7 steps (finiteness), and every step is clear, for example "wait 3 minutes" instead of "wait a while" (definiteness). Each step is also something a person can actually do (effectiveness). Your answer can have different steps, as long as it keeps these properties.
