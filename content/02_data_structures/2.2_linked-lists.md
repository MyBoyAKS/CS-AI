## Key terms

| Term | Meaning (one line, plain words) |
|---|---|
| **Memory** | The part of the computer that stores data while a program runs. |
| **Place in memory** | One spot in memory where a value can be stored. Each place has its own number, so the computer can find it. |
| **Linked list** | A list of items where each item says where the next item is, so the items can be anywhere in memory. |
| **Node** | One box in a linked list. It holds one item of data and one pointer. |
| **Data** | The item a node stores (called an element in 2.1), such as a name or a number. |
| **Pointer** | The part of a node that says which node comes next. Also called the "next" link. |
| **Head** | A pointer to the first node. It is where every search through the list must start. |
| **Null** | A special "nothing" value. A pointer set to null means "there is no next node". |
| **End (tail)** | The last node in the list. Its pointer is null. |
| **Empty list** | A list with no nodes. Its head is null. |
| **Traversal** | Visiting the nodes one by one by following the pointers, starting from the head. |
| **Position** | Which node it is when counting from the head: the 1st node, the 2nd node, and so on. A linked list has no index to jump to. Position 1 is the same item as index 0 in an array. |

## 2.2.1 Why does this matter? (the problem)

In Chapter 2.1, we inserted the score 70 at index 1 of an array. Four other scores had to shift one place to the right to make room. Inserting at the front would need every item to shift.

| Items in the array (with one free position) | Insert at the front: shifts needed |
|---|---|
| 5 | 5 |
| 100 | 100 |
| 1,000,000 | 1,000,000 |

The more items an array has, the more items need to be moved. Deleting has the same problem in reverse: every item after the gap must shift one place to the left to close it.

There is a second problem. A classic array has a **fixed size**. If all positions are full, nothing more can be added.

A **linked list** solves both problems. Adding or removing an item does not move any other item. And the list can keep growing, one node at a time.

But nothing is free. A linked list makes a different job slower: finding the item at a certain position. This chapter shows both sides.

## 2.2.2 The idea

### Linked lists: a treasure hunt

Imagine a treasure hunt. You are given the first clue. It does not say where every clue is. It only says where the **next** clue is hidden: "Look under the blue chair." Under the chair, you find a second clue: "Look behind the clock." You keep following clues until one says "This is the end."

A linked list works the same way:

- Each clue is a **node**. It holds some **data** (the message) and a **pointer** (where the next clue is).
- The location of the first clue is the **head**. Without it, you cannot start.
- The last clue says "the end". In a linked list, the last node is called the **tail**, and its pointer is **null**, which means "there is no next node".

Here is a linked list of four names:

```text
 head
  |
  v
+------+---+     +------+---+     +------+---+     +------+------+
| Ayu  | o-+---->| Budi | o-+---->| Chen | o-+---->| Dewi | null |
+------+---+     +------+---+     +------+---+     +------+------+
 data   next      data   next      data   next      data   next
```

Each box is a node. The left part is the data. The right part is the pointer, shown as an arrow to the next node. Dewi is the tail.

### Inside the computer

In an array, the items sit next to each other, like the lockers in Chapter 2.1. In a linked list, the nodes can be anywhere in memory. The pointers show which node comes next and keep the list in the correct order.

The table below shows the same list as it might be stored. The "place" numbers stand for places in memory. They are made up for this example.

| Place in memory | Data | Next (pointer) |
|---|---|---|
| 12 | Budi | 71 |
| 25 | Dewi | null |
| 40 | Ayu | 12 |
| 71 | Chen | 25 |

The head says **40**. So the computer starts at place 40 (Ayu), then goes to 12 (Budi), then 71 (Chen), then 25 (Dewi). Dewi's pointer is null, so the list ends there.

Notice that the nodes are **not** stored in order. The order comes only from the pointers.

### Where the analogy stops working

- **Real clues are fixed.** Once a treasure hunt starts, nobody rewrites the clues. In a linked list, changing a pointer is the normal way to add or remove a node. That is the whole point.
- **In a treasure hunt, only the last clue holds the prize.** In a linked list, every node holds data. The tail is not special, except that its pointer is null.
- **You walk between real clues, so distance matters.** A computer does not walk. Following one pointer takes the same short time, wherever the next node is. What matters is **how many** pointers it must follow.
- **A lost clue can still be found by searching the room.** In a linked list, if no pointer leads to a node, the computer can never find that node again. This is why the order of steps matters when we change pointers.

### Arrays and linked lists side by side

| | Array (Chapter 2.1) | Linked list |
|---|---|---|
| How items are stored | Next to each other, in order | Anywhere in memory, connected by pointers |
| How to reach an item | Jump straight to its index | Start at the head and follow pointers |
| Where to start | Any index | Always the head |
| Size | Fixed when created | Can grow one node at a time |
| Everyday model | A row of numbered lockers | A treasure hunt |

## 2.2.3 How it works, step by step

### Finding the node at a position (traversal)

A linked list has no index to jump to. To reach a node, the computer must follow the chain from the head.

1. **Start at the head.** If the head is null, the list is empty. Stop: there is nothing to find.
2. **Follow the head** to the first node. Count it as position 1.
3. **Is this the position you want?** If yes, stop and return its data.
4. **If not, look at this node's pointer.**
5. **If the pointer is null, stop.** The list has ended, so the position does not exist.
6. **Otherwise, follow the pointer** to the next node, add 1 to the count, and go back to step 3.

Following the head is the first step. After that, reaching position n means following **n - 1 pointers**, so n steps in total.

| Find the item at... | Array (Chapter 2.1) | Linked list |
|---|---|---|
| Position 1 (index 0) | 1 step: jump to index 0 | 1 step: follow the head |
| Position 5 (index 4) | 1 step: jump to index 4 | 5 steps: follow the head, then 4 pointers |
| Position 1,000 (index 999) | 1 step: jump to index 999 | 1,000 steps: follow the head, then 999 pointers |

An array is much faster here. It works out where index 4 is and goes straight there. A linked list cannot, because the nodes can be anywhere in memory. Only the pointers know the way.

### Finding a node by its data

Sometimes you do not know the position. You only know the data, for example "find Chen". The steps are almost the same, but you compare the data instead of counting.

1. **Start at the head.** If the head is null, the list is empty. Stop: the item is not there.
2. **Follow the head** to the first node.
3. **Does this node's data match what you want?** If yes, stop and return this node.
4. **If not, look at this node's pointer.**
5. **If the pointer is null, stop.** The list has ended, so the item is not in the list.
6. **Otherwise, follow the pointer** to the next node and go back to step 3.

This is linear search from Chapter 1.3, done by following pointers instead of indexes. When searching by data, an array must also check its items one by one (unless it is sorted), so here the two are much closer.

### Inserting a node after a given node

Say we want to put a new node between node B and node C.

1. **Make the new node** and put the data in it.
2. **Point the new node at C.** Copy B's pointer into the new node's pointer.
3. **Point B at the new node.**

No other nodes need to move. C and the nodes after it stay in the same place.

Why must step 2 come **before** step 3? If B is pointed at the new node first, the only pointer to C is gone. Nothing leads to C any more, so C and every node after it are lost.

**Special case: inserting at the front.** Point the new node at the current first node, then point the head at the new node.

### Deleting a node

Say we want to remove node C. The node before it is B.

1. **Check the first node first.** If the node to delete is the first node, no node comes before it. Point the head at the second node, and stop.
2. **Check B's pointer.** If it is null, B is the tail, so no node comes after it. Stop: there is nothing to delete.
3. **Point B at the node after C.** Copy C's pointer into B's pointer.

That is all. B now skips over C. Nothing leads to C any more, so it is no longer part of the list. Nothing else moves.

### The catch: you must find the spot first

Changing pointers takes only one or two steps. But to change B's pointer, the computer must first **reach** B. If you only know a position ("insert at position 5"), it must follow the chain to get there.

| Job | Array (Chapter 2.1) | Linked list |
|---|---|---|
| Find the item at position 5 | Fast: jump straight there | Slow: follow the head, then 4 pointers |
| Insert or delete, once you are at the right spot | Slow: shift every item after it | Fast: change 1 or 2 pointers |
| Insert at the front | Slowest: shift every item | Fastest: change 2 pointers, no searching |
| Add an item when all space is used | Not possible (fixed size) | Possible: make a new node |

### Optional: the same ideas in Python

How to read it: `class` describes what every node looks like, `__init__` runs when a new node is made, `self` means "this node", `while` repeats the indented lines, and `is not None` checks that the pointer is not null.

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None        # None is Python's null

ayu = Node("Ayu")
budi = Node("Budi")
chen = Node("Chen")
ayu.next = budi                 # Ayu points to Budi
budi.next = chen                # Budi points to Chen
head = ayu

# Traversal: print every name
node = head
while node is not None:
    print(node.data)            # Ayu, Budi, Chen
    node = node.next

# Insert "Bea" after Ayu
bea = Node("Bea")
bea.next = ayu.next             # step 2: Bea points to Budi
ayu.next = bea                  # step 3: Ayu points to Bea

# Delete the node after Bea (Budi)
bea.next = bea.next.next        # Bea now points to Chen
```

Note: Python already has a list that works like a growable array, so you rarely build a linked list by hand. The class above is only to show the idea.

## 2.2.4 Worked example 1: inserting in the middle

Here is a linked list of 4 names. The places in memory are the same as in 2.2.2 (Inside the computer).

```text
head -> Ayu -> Budi -> Chen -> Dewi -> null
```

**Task:** Insert the name **Bima** after Budi, so Bima becomes the 3rd name.

| Step | What happens | State after the step |
|---|---|---|
| 1 | Start at the head. The current node is Ayu (position 1). It is not Budi. | `head -> Ayu -> Budi -> Chen -> Dewi -> null` |
| 2 | Follow Ayu's pointer. The current node is Budi (position 2). Found the node to insert after. | List unchanged |
| 3 | Make a new node with the data Bima. Its pointer is null for now. It is not in the list yet. | List unchanged. Separately: `Bima -> null` |
| 4 | Copy Budi's pointer into Bima's pointer. Bima now points to Chen. | List unchanged. Separately: `Bima -> Chen` |
| 5 | Point Budi at Bima. | `head -> Ayu -> Budi -> Bima -> Chen -> Dewi -> null` |

**Expected result:** `Ayu, Budi, Bima, Chen, Dewi`. The insert needed **1 pointer followed** after the head to reach Budi and **2 pointer changes** (steps 4 and 5). **No node moved.**

Here are the pointers around Budi before and after:

```text
Before:
    Budi -------------------> Chen

After step 4 (Bima points to Chen):
    Budi -------------------> Chen
                               ^
                   Bima -------+

After step 5 (Budi points to Bima):
    Budi                      Chen
     |                         ^
     v                         |
    Bima ----------------------+
```

You can see this in memory. Say the computer stores Bima at place 58:

| Place in memory | Data | Next: before | Next: after |
|---|---|---|---|
| 40 | Ayu | 12 | 12 |
| 12 | Budi | 71 | **58** |
| 58 | Bima | (did not exist) | **71** |
| 71 | Chen | 25 | 25 |
| 25 | Dewi | null | null |

Only two pointers changed. Every node stayed in the same place.

**Watch out:** If step 5 is done before step 4, Budi points to Bima, and Bima points to null. Nothing points to Chen any more, so Chen and Dewi are lost. Always connect the new node to the rest of the list **first**.

**Compared with an array:** If the index is already known, inserting Bima at index 2 of an array would shift Chen and Dewi one place to the right: 2 shifts. That sounds small. But if 1,000 names came after Budi, the array would need 1,000 shifts. The linked list would still need only 2 pointer changes.

## 2.2.5 Worked example 2: deleting a node

We continue with the list from Worked example 1.

```text
head -> Ayu -> Budi -> Bima -> Chen -> Dewi -> null
```

**Task:** Delete the node with the name **Chen**.

To delete Chen, we must change the pointer of the node **before** Chen. So at each node we ask: "Is the next node Chen?"

| Step | What happens | State after the step |
|---|---|---|
| 1 | Start at the head. The current node is Ayu. It is not the node to delete. Its next node is Budi, not Chen. | `head -> Ayu -> Budi -> Bima -> Chen -> Dewi -> null` |
| 2 | Follow Ayu's pointer. The current node is Budi. Its next node is Bima, not Chen. | List unchanged |
| 3 | Follow Budi's pointer. The current node is Bima. Its next node is Chen. Found the node before Chen. Peeking at the next node's data to check the name does not count as following a pointer: the computer stays at Bima. | List unchanged |
| 4 | Copy Chen's pointer into Bima's pointer. Bima now points to Dewi and skips Chen. | `head -> Ayu -> Budi -> Bima -> Dewi -> null` |

**Expected result:** `Ayu, Budi, Bima, Dewi`. The delete needed **2 pointers followed** after the head to reach Bima and **1 pointer change** (step 4). **No node moved.** Chen still sits in memory for a moment, but nothing points to it, so it is no longer part of the list.

**Two other cases:**

| Case | What to do |
|---|---|
| The name is not in the list, for example "Fajar" | Keep following pointers. When a pointer is null, the list has ended. Fajar was not found, so nothing is deleted. |
| Delete the first node, Ayu | No node comes before Ayu, so point the **head** at Ayu's next node (Budi). |

**Compared with an array:** If the index is already known, deleting Chen from index 3 of an array would shift Dewi one place to the left to close the gap. Deleting from the front would shift every other item.

| Job in examples 1 and 2 | Array (index already known) | Linked list |
|---|---|---|
| Insert Bima after Budi | 2 shifts (Chen, Dewi) | 1 pointer followed, 2 pointer changes |
| Delete Chen | 1 shift (Dewi) | 2 pointers followed, 1 pointer change |
| Same jobs with 1,000 names after the spot | 1,000 shifts | Same pointer changes as above |

The array column does not count finding the spot. If the array only knew the name, it would also have to check items one by one to find the index first.

## 2.2.6 Common misunderstandings

| Mistake | Why it is wrong | Correct idea |
|---|---|---|
| "A linked list stores its items next to each other, like an array." | The nodes can be anywhere in memory. In 2.2.2 (Inside the computer), Ayu was at place 40 and Budi at place 12. | The order comes only from the **pointers**, not from where the nodes are stored. |
| "To get the 5th item, jump straight to it, like index 4 in an array." | A linked list has no index. Only the 4th node knows where the 5th node is. | Follow the **head**, then **4 pointers**. Reaching position n means following n - 1 pointers after the head. |
| "Inserting a node means moving the nodes after it to make room." | That is what an array does. In a linked list, the new node can go anywhere in memory. | **No node moves.** Only two pointers change: the new node's and the one before it. |
| "Inserting into a linked list is always fast." | Changing the pointers is fast. But the computer must first reach the right spot by following the chain. | Fast **once you are at the spot**. Getting there can take many steps, except at the front. |
| "The order of the pointer changes does not matter." | If the node before is pointed at the new node first, nothing points to the rest of the list any more. | Point the **new node** at the next node **first**. Then point the node before at the new node. |
| "To delete a node, change that node's own pointer." | Other nodes still point to it, so it stays in the list. | Change the pointer of the node **before** it, so the list skips over it. |
| "Null is the last node." | Null is not a node. It holds no data. | Null is the "nothing" value in the **tail's pointer**. It means "there is no next node". |
| "The head is the first node." | The head is not a node and holds no data. It only says where the first node is. | The head is a **pointer** to the first node. In an empty list, the head is null. |
| "A linked list is always better than an array." | Each one is fast at different jobs. | Use an **array** when you often read by position. Use a **linked list** when you often insert or delete, especially at the front. |

## 2.2.7 Learner activity

**Goal:** Practise traversal, inserting and deleting by acting out a linked list, and see why the order of pointer changes matters.

**You need:**

- 7 learners to act, plus the rest of the class as recorders. A large class can split into groups of 8 to 10.
- For each acting learner, two pieces of paper: a **data card** and a **next card**. A marker or pen.
- One extra paper for the **head card**.
- Time: about 20 minutes.

**Roles:**

| Role | Who | What they do |
|---|---|---|
| Node | 6 learners: 4 at the start, 2 join later | Hold a data card (a fruit name) and a next card (the name of the next node, or "null"). |
| Head | The teacher or 1 learner | Holds the head card, which names the first node. |
| Computer | 1 learner | Finds nodes. May only read the head card first, then the next card of the node they are standing at. May not skip anyone or ask "where is cherry?" |
| Recorders | Everyone else | Write down what happens in each round. |

**Setup:**

1. Give 4 node learners these data cards: **apple, banana, cherry, date**. Keep a fifth learner aside with the data card **mango**. Keep a sixth aside with **kiwi**.
2. Ask the 4 nodes to stand in **different places around the room**, not in a line. This is like memory in 2.2.2 (Inside the computer): nodes can be anywhere.
3. Fill in the next cards: apple says "banana", banana says "cherry", cherry says "date", date says "null". The head card says "apple". New nodes (mango and kiwi) start with "null" on their next card.
4. Everyone checks the list together: `head -> apple -> banana -> cherry -> date -> null`.

**Task:**

**Round 1: find a position.**

1. The computer finds the node at **position 4**. They read the head card, walk to apple and say "position 1". At each node, they read its next card aloud, walk to that node and say the next position number. They stop at position 4 without reading its card. Recorders count how many next cards the computer reads.
2. Now the 4 nodes sit in a row of chairs numbered 0 to 3, in order, like an array. The computer points straight at chair 3. Recorders compare the two ways.
3. The nodes go back to their places around the room.

**Round 2: insert in the middle.**

4. Insert **mango** after apple. The mango learner enters and stands anywhere. Follow the steps from 2.2.3 in order: first mango writes on their next card, then apple changes their next card. Recorders write which cards changed and how many nodes already in the list moved.
5. The computer walks the whole list from the head to check it.

**Round 3: delete a node.**

6. Delete **cherry**. The computer starts at the head and stops at the node whose next card says "cherry". That node changes their next card. Cherry sits down.
7. The computer walks the whole list again to check it.

**Round 4: find the error.**

8. Insert **kiwi** after mango, but do it in the **wrong order** on purpose: mango changes their next card to "kiwi" **first**. Kiwi's next card still says "null".
9. The computer walks the list from the head. Any node the computer does not reach sits down.
10. Discuss: Can the computer find the seated nodes again? Why not? What should have happened instead?

**Record:** For each round, write:

- the list after the round, from head to null,
- how many next cards the computer read,
- which cards changed, and how many nodes already in the list moved.

Then answer:

- **Q1.** In Round 1, how many next cards did the computer read to reach position 4? How many steps did the array need?
- **Q2.** In Round 2, which next cards changed? How many nodes already in the list had to move?
- **Q3.** In Round 3, whose next card changed, and what did it say after?
- **Q4.** In Round 4, which nodes were lost, and why? Write the correct order of the two card changes.

**Teacher notes:**

- Stop the computer if they skip ahead or look around the room for a name. In a real linked list, the computer cannot see where the nodes are. It only knows what the current next card says.
- In Round 4, the class will "remember" where banana and date are standing. Point out that a computer does not: if no pointer leads to a node, it is gone.
- To reset quickly, keep a photo or a list of the starting cards.

**Solo version (paper only):** For a learner working alone, or as homework.

1. On a blank page, draw 4 node boxes in random spots, not in a row: apple, banana, cherry, date. Give each box a next part. Draw the head arrow to apple, then arrows from apple to banana, banana to cherry and cherry to date. Write "null" in date's next part.
2. **Round 1:** Put your finger on the head and follow the arrows to position 4. Count the arrows you follow after the head.
3. **Round 2:** Draw mango anywhere, with "null" in its next part. Draw mango's arrow to banana first. Then cross out apple's arrow and draw a new one from apple to mango.
4. **Round 3:** Cross out banana's arrow to cherry and draw a new one from banana to date.
5. **Round 4:** Draw kiwi, with "null" in its next part. Cross out mango's arrow and draw a new one to kiwi **first**. Now trace from the head and circle every node you cannot reach.

Use the same Record list and Q1 to Q4. The answers are the same as for the class version.

## 2.2.8 Check your understanding

1. A linked list holds `head -> P -> Q -> R -> S -> T -> null`.
   - a) After following the head, how many more pointers must the computer follow to reach the node at position 4? Which node is it?
   - b) The same five letters are stored in an array. How many steps does it take to read the item at index 3?
2. A linked list holds `head -> 10 -> 20 -> 40 -> null`. You want to insert **30** after 20.
   - a) Write the two pointer changes, in the correct order.
   - b) Write the final list from head to null.
   - c) How many nodes had to move?
3. A linked list holds `head -> K -> L -> M -> null`.
   - a) Delete **K**. Which pointer changes, and what does it point to after? Write the final list.
   - b) Now try to delete **Z** from the new list. What happens, and how does the computer know?
4. For each situation, choose **an array** or **a linked list**. Explain your choice.
   - a) A music app has a playlist of 500 songs. Users often jump straight to a song by its number, such as song 250. The playlist rarely changes.
   - b) A chat app keeps a list of recent messages. Every new message is added at the front, and messages are often removed from the middle.

## 2.2.9 Answers and explanations

### Learner activity (2.2.7)

**Q1. 3 next cards. The array needed 1 step.**
The computer reads the head card and goes to apple (position 1). Then it reads apple's next card and goes to banana (position 2), banana's to cherry (position 3) and cherry's to date (position 4). It stops at date without reading date's card. That is 3 next cards, because reaching position n needs n - 1 pointers after the head. In the array, the computer points straight at chair 3, so it takes 1 step.

**Q2. Two cards changed: mango's and apple's. No node already in the list moved.**
Mango's next card was set to "banana" first (copied from apple's card). Then apple's next card changed from "banana" to "mango". Only mango walked in, and it could stand anywhere. Apple, banana, cherry and date stayed where they were.
List after Round 2: `head -> apple -> mango -> banana -> cherry -> date -> null`

**Q3. Banana's next card changed from "cherry" to "date".**
The computer followed the chain until it reached the node whose next card said "cherry": that was banana. Banana copied cherry's next card ("date"), so the list now skips cherry. Only one card changed.
List after Round 3: `head -> apple -> mango -> banana -> date -> null`

**Q4. Banana and date were lost.**
Mango's next card was the only pointer to banana. When mango changed it to "kiwi" first, nothing pointed to banana any more, and kiwi's card said "null". So the computer walked `apple -> mango -> kiwi -> null` and never reached banana or date.
Correct order:

1. Kiwi copies mango's next card, so kiwi's card says "banana".
2. Mango changes their next card to "kiwi".

Correct list: `head -> apple -> mango -> kiwi -> banana -> date -> null`

### Check your understanding (2.2.8)

1. a) **3 pointers. The node is S.** Following the head reaches P (position 1). Then P's pointer reaches Q (2), Q's reaches R (3), and R's reaches S (4). Position 4 needs 4 - 1 = 3 pointers after the head.
   b) **1 step.** An array jumps straight to index 3, which is also S. This is the main thing an array does better than a linked list.
2. a) **First**, point 30 at 40 (copy 20's pointer into 30's pointer). **Then** point 20 at 30. If 20 were changed first, nothing would point to 40, and 40 would be lost.
   b) `head -> 10 -> 20 -> 30 -> 40 -> null`
   c) **None.** Only two pointers changed. To reach 20, the computer followed 1 pointer after the head, but no node moved.
3. a) **The head changes. It now points to L.** K is the first node, so no node comes before it. The head copies K's pointer, so it skips K. Final list: `head -> L -> M -> null`
   b) **Nothing is deleted.** The computer starts at L, which is not Z. It follows L's pointer to M, which is not Z. M's pointer is null, so the list has ended. That is how the computer knows Z is not in the list.
4. a) **An array.** Users jump to a song by its number. An array reaches song 250 (index 249) in 1 step. A linked list would follow the head and then 249 pointers. Because the playlist rarely changes, the array's slow shifting does not matter much.
   b) **A linked list.** Adding at the front only changes 2 pointers, while an array would shift every message. Removing from the middle changes 1 pointer once the spot is reached, while an array would shift every message after the gap.

## 2.2.10 Summary

- A **linked list** is a chain of **nodes**. Each node holds some **data** and a **pointer** to the next node. The **head** points to the first node, and the tail's pointer is **null**.
- The nodes can be anywhere in memory. The **pointers** decide the order.
- **Finding** the node at position n means following the head and then **n - 1 pointers**. An array does this in 1 step.
- **Inserting** changes 2 pointers and **deleting** changes 1 pointer, once you are at the right spot. No node moves. An array must shift every item after the spot.
- When inserting, point the **new node** at the next node **first**, or the rest of the list is lost.
