## Key terms

| Term | Meaning (one line, plain words) |
|---|---|
| **Variable** | A named place in memory that stores one value. |
| **Array** | A list of items stored in order, where each item has its own number. |
| **Element** | One item stored in an array. |
| **Index** | The number of a box. It says how far the box is from the start of the array. |
| **Zero-based indexing** | Counting indexes from 0, so the first element is at index 0. |
| **Length** | How many elements the array holds. |
| **Fixed size** | The number of items is decided when the array is created and cannot be changed. |
| **Shifting** | Moving elements one box over to make room for a new item or to close a gap. |
| **Out of range** | Asking for an index that does not exist, such as index 5 in an array of length 5. |
| **Record** | A group of related values about one thing, each value with a name. Like one row in a spreadsheet. |
| **Field** | One named value inside a record. Like one column in a spreadsheet. |
| **Array of records** | An array where every element is a record. Like a whole spreadsheet table. |

## 1. Why does this matter? (the problem)

A teacher has 5 students and wants to store their test scores. One way is to make five separate variables: `score1`, `score2`, `score3`, `score4`, `score5`. This works for 5 students. But what about 300 students? Creating 300 separate variables takes a lot of time and can easily lead to mistakes.

There is a second problem. A student is more than a score. Each student also has a name and a student ID. If these are stored in three unrelated places, it is easy to mix up whose score belongs to whom.

This section solves both problems:

- An **array** keeps many items of the same kind together, in order, under one name.
- A **record** keeps all the details about one thing together, each with a name.

## 2. The idea

### Arrays: a row of numbered lockers

Imagine a row of lockers in a school hallway. Each locker has a number painted on it, and each locker holds one item. To get an item, you do not search every locker. You go straight to the locker with the right number.

An array works the same way. Each element sits in its own position, and each position has a number called its **index**.

In most programming languages, the first index is **0**, not 1. **The index shows the position of an item, starting from 0.** An easy way to see why: count how many steps the item is from the start.

- The first element is right at the start. It is 0 steps away, so its index is 0.
- The second element is 1 step away, so its index is 1.
- The third element is 2 steps away, so its index is 2.

Here is an array called `scores` with 5 elements:

```text
start
  |
  v
+------+------+------+------+------+
|  82  |  75  |  91  |  68  |  88  |
+------+------+------+------+------+
index:  0      1      2      3      4
```

The array has a **length** of 5, but the last index is 4. This is always true: **last index = length - 1**.

### Where the analogy stops working

- **Real lockers can hold anything.** One locker may hold a bag, the next a guitar. In an array, every element is usually the same kind of item, for example all numbers or all names.
- **You walk to a real locker.** Locker 50 takes longer to reach than locker 1. A computer does not walk. It calculates the position from the index, so reaching index 0 and index 999 takes the same short time.
- **Real lockers usually start at 1.** Array indexes start at 0, because they count distance from the start.

### Records: one row in a spreadsheet

A **record** stores several values about one thing. Each value has a name, called a **field**.

Think of a spreadsheet. Each **column** is a field. Each **row** is one record.

| name | student_id | score |
|---|---|---|
| Ayu | S001 | 82 |
| Budi | S002 | 75 |
| Chen | S003 | 91 |

- The row `Ayu, S001, 82` is **one record**.
- `name`, `student_id` and `score` are its **fields**.
- The whole table is an **array of records**: an array where each element is one student's record.

Fields are found by **name**, not by number. You ask for "Ayu's score", not "Ayu's item number 2". This makes records easy to read and hard to mix up.

## 3. How it works, step by step

### Reading an element by index

1. **Check the index.** It must be between 0 and length - 1. If not, it is out of range and there is no element to read.
2. **Go straight to that position.** The computer does not check the earlier elements first.
3. **Return the element.** The array does not change.

### Inserting an element into the middle

A classic array has a fixed size, so it must already have a free (empty) position at the end. Then:

1. **Check there is a free position.** If the array is full, the new item cannot be added.
2. **Shift elements to the right.** Start with the last element and move it one position right. Then move the one before it. Keep going until the target index is empty.
3. **Put the new item** at the target index.
4. **Count it.** The number of stored items goes up by 1.

Why start shifting from the **end**? If you started at the front, each element would be copied over the next one, and the next one would be lost.

### Reading a field from a record

1. **Find the record.** In an array of records, use the index, for example the record at index 1.
2. **Ask for the field by its name**, for example `score`.
3. **Return the value** stored in that field.

### Optional: the same ideas in Python

```python
scores = [82, 75, 91, 68, 88]
print(scores[2])          # 91, the element at index 2
print(len(scores))        # 5, the length

scores.insert(1, 70)      # put 70 at index 1, the others shift right
print(scores)             # [82, 70, 75, 91, 68, 88]

student = {"name": "Ayu", "student_id": "S001", "score": 82}
print(student["score"])   # 82, the field called score

class_list = [
    {"name": "Ayu",  "student_id": "S001", "score": 82},
    {"name": "Budi", "student_id": "S002", "score": 75},
]
print(class_list[1]["name"])   # Budi, the record at index 1, field name
```

Note: a Python list can grow, so `insert` works even without a free position. Python still shifts the elements for you behind the scenes. A Python **dictionary** (the part in `{ }`) is a simple way to write a record.

## 4. Worked example 1: reading the record at index 2

Here is a class list stored as an array of 5 student records:

| index | name | student_id | score |
|---|---|---|---|
| 0 | Ayu | S001 | 82 |
| 1 | Budi | S002 | 75 |
| 2 | Chen | S003 | 91 |
| 3 | Dewi | S004 | 68 |
| 4 | Eko | S005 | 88 |

**Question:** What is the score of the student at index 2?

| Step | What happens | State after the step |
|---|---|---|
| 1 | Check the index. The length is 5, so valid indexes are 0 to 4. Index 2 is valid. | Class list unchanged |
| 2 | Go straight to index 2. No earlier records are checked. | Found the record `Chen, S003, 91` |
| 3 | Ask this record for the field called `score`. | Value found: `91` |
| 4 | Return the value. | Result is **91**. Class list unchanged |

**Expected result:** The score is **91**. The student at index 2 is Chen, the **third** student in the list, because index 2 means "2 steps from the start".

**Watch out:** If you count from 1 by mistake, you pick the second student, Budi, and get 75. That is the wrong answer.

## 5. Worked example 2: inserting into the middle

An array called `scores` has a fixed size of **6** positions. It holds 5 scores, so the last position is empty. In the table, `_` means an empty position.

```text
scores:  82   75   91   68   88   _
index:    0    1    2    3    4   5
```

**Task:** Insert the score **70** at index 1.

| Step | What happens | State after the step (index 0 to 5) |
|---|---|---|
| 1 | Check for a free position. Index 5 is empty, so there is room. | `82, 75, 91, 68, 88, _` |
| 2 | Shift the last element: move 88 from index 4 to index 5. | `82, 75, 91, 68, _, 88` |
| 3 | Move 68 from index 3 to index 4. | `82, 75, 91, _, 68, 88` |
| 4 | Move 91 from index 2 to index 3. | `82, 75, _, 91, 68, 88` |
| 5 | Move 75 from index 1 to index 2. Index 1 is now empty. | `82, _, 75, 91, 68, 88` |
| 6 | Put 70 at index 1. | `82, 70, 75, 91, 68, 88` |
| 7 | Count the items: 5 + 1 = 6. The array is now full. | `82, 70, 75, 91, 68, 88` |

**Expected result:** `82, 70, 75, 91, 68, 88`. Inserting one item needed **4 shifts**.

**Why this matters:** Reading an element always takes one step (example 1). Inserting depends on the position:

| Insert at | Elements that must shift |
|---|---|
| Index 0 (the front) | 5 |
| Index 1 (this example) | 4 |
| Index 5 (the end) | 0 |

Inserting an item closer to the beginning requires moving more elements. If the array were already full, the insert could not happen at all, because a fixed-size array cannot grow.

## 6. Common misunderstandings

| Mistake | Why it is wrong | Correct idea |
|---|---|---|
| "The first element is at index 1." | The index shows how many steps the item is from the start. The first item is 0 steps away. | The first index is **0**. The last index is **length - 1**. |
| "An array of length 5 has an index 5." | The indexes are 0, 1, 2, 3, 4. That is already 5 positions. | Index 5 is **out of range**. There is no element there. |
| "To read index 3, the computer checks index 0, 1 and 2 first." | The computer calculates the position from the index and goes straight there. | Reading any index takes the **same short time**. |
| "Inserting is as fast as reading." | Every element after the new position must shift one place to the right. | Inserting near the beginning can take **many steps**. Reading takes one. |
| "An array can always grow, like a Python list." | A classic array has a fixed size. Python lists hide this: when a list gets full, Python makes a bigger one and copies the items over for you. | A classic array **cannot grow**. If it is full, nothing more can be added. |
| "A record is just another array." | An array holds many items of the same kind, found by number. A record holds different details about one thing, found by name. | Array: find by **index**. Record: find by **field name**. |
| "The field name is the data." | `score` is only the label. The data is the value stored under it, such as 91. | A field has a **name** and a **value**. |

| Step | What the student did | State after the step |

## 9. Answers and explanations

### Learner activity (section 7)

**Part A**

1. **date.** Count steps from the start: apple is 0 steps away, banana 1, cherry 2, date 3.
2. **It is out of range.** The array has 5 positions, so the indexes are 0 to 4. There is no index 5, so there is nothing to read.
3. **3 shifts.** Index 4 is free, so there is room. The items from index 1 to 3 must each move one place right, starting from the end:

| Step | What happens | State after the step (index 0 to 4) |
|---|---|---|
| 1 | Move date from index 3 to index 4 | `apple, banana, cherry, _, date` |
| 2 | Move cherry from index 2 to index 3 | `apple, banana, _, cherry, date` |
| 3 | Move banana from index 1 to index 2 | `apple, _, banana, cherry, date` |
| 4 | Put mango at index 1 | `apple, mango, banana, cherry, date` |

The array is now full.

**Part B**

4. **The error is in step 1.** The student shifted from the **front**. Moving 20 into index 1 wrote over 30, so **30 was lost**. That is why step 2 skips 30 and index 2 ends up empty.
5. **Correct trace:** start from the **end**, so every item moves into an empty position.

| Step | What happens | State after the step (index 0 to 3) |
|---|---|---|
| 1 | Move 40 from index 2 to index 3 | `20, 30, _, 40` |
| 2 | Move 30 from index 1 to index 2 | `20, _, 30, 40` |
| 3 | Move 20 from index 0 to index 1 | `_, 20, 30, 40` |
| 4 | Put 50 at index 0 | `50, 20, 30, 40` |

Final array: `50, 20, 30, 40`. Inserting at the front needed 3 shifts, one for every item.

**Part C**

6. **Eko.** Index 4 is the fifth record: Ayu (0), Budi (1), Chen (2), Dewi (3), Eko (4).
7. **Index 3, field `student_id`, value S004.** The index finds Dewi's record. The field name finds the right detail inside it.

### Check your understanding (section 8)

1. **Last index: 7. The 4th element: index 3.** The last index is always length - 1, so 8 - 1 = 7. The 4th element is 3 steps from the start, so its index is 3.
2. **4 shifts. Final array: `10, 20, 25, 30, 40, 50, 60`.** Every item from index 2 to index 5 (30, 40, 50, 60) must move one place right, starting with 60. Then 25 goes into index 2. The array now holds 7 items and is full.
3. Choosing a structure:
   - a) **A single array.** There are many values of the same kind (temperatures), and their order matters (day 1, day 2, and so on).
   - b) **A single record.** These are different details (title, author, year) about one thing.
   - c) **An array of records.** Each student is one record with the same fields, and the array holds all the students, like the class list in Worked example 1.

## 10. Summary

- An **array** stores many items of the same kind, in order. Each item has an **index**, starting from 0, so the last index is **length - 1**.
- **Reading** an item by its index takes one step, because the computer goes straight to that position.
- **Inserting** into the middle means **shifting** every item after that position one place to the right, starting from the end. A classic array has a **fixed size**, so it needs a free position first.
- A **record** groups different details about one thing. Each detail is a **field**, found by its name, like a column in a spreadsheet.
- An **array of records** stores many records in order, like a whole spreadsheet table. Use the index to find the record, then the field name to find the detail.
